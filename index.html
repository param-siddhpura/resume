Architecture Specification Applied AI Systems

College Notes AI Assistant: RAG Pipeline Design

A system architecture designed to solve hallucination and courseware irrelevance by grounding LLM responses strictly inside indexed academic documents with traceable source citations.

Problem Statement & Motivation

Undergraduate engineering students frequently face exam-time information overload across 500+ pages of lecture slide PDFs and syllabus notes. Standard commercial LLMs generate convincing yet factually divergent or out-of-syllabus answers. The objective of this project is to build an application that restricts answers to uploaded course materials, returns exact page numbers, and refuses to answer when context is insufficient.

Key Engineering Trade-offs & Decisions

  • Chunk Sizing: Fixed 500-token chunks with 50-token overlaps to preserve semantic continuity across formula explanations without overflowing embedding token bounds.
  • Metadata Tagging: Preserving source file name, section headers, and slide page indices inside each vector record for instant citation generation.
  • Strict Prompt Guardrails: System instructions forbidding speculation: "Answer only from the retrieved context. If absent, explicitly respond: 'Information not found in course notes'."

Evaluation Framework (RAG Triad)

Evaluation will be benchmarked using the RAG Triad framework: Context Relevance (verifying retrieved chunks match query intent), Groundedness (verifying claims in the response are directly supported by context), and Answer Relevance (verifying the answer addresses the student's question).

Proposed Execution Flow Spec v1.0
1. PDF Parsing & OCR Extract raw text & slide hierarchy
↓
2. Semantic Chunking 500 tokens + 50 overlap + metadata
↓
3. Dense Vector Indexing ChromaDB / FAISS vector space
↓
4. Top-k Semantic Query Cosine similarity retrieval
↓
5. Context-Fused LLM Inference Strict system prompt + source citation
↓
6. Verification & Student UI JSON response with citations
